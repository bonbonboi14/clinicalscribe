# ADR-0011: Transcript-grounded treatment plan generation

## Status

Accepted — Phase 9.

## Decision

Treatment plans are generated by a dedicated `TREATMENT_PLAN` worker after note generation. The worker reads immutable structured facts and accepts only facts in the `TREATMENT` and `PLAN` categories. It never reads diagnoses to select or complete treatment.

The persisted plan is immutable and contains these sections:

- non-pharmacological
- pharmacological (`drug`, `dose`, `route`, `frequency`, `duration`, `source_transcript_ref`)
- investigations ordered
- referrals
- follow-up
- patient education
- pending decisions

Every non-placeholder value carries a structured-fact reference in `evidence_by_field`. Medication entries additionally expose their transcript segment directly as `source_transcript_ref`. Missing information is rendered as `Not mentioned.`

Before persistence, `TreatmentDoNotInferValidator` checks exact value provenance and `NoteValidator.validate_treatment_plan()` classifies each claim. The hallucination firewall rejects `UNSUPPORTED` and `CONTRADICTED` claims. `TREATMENT_PLAN_GENERATED` is written only after those checks pass.

## Review contract

The review API and UI present two panes in this order:

`TRANSCRIPT | TREATMENT PLAN`

The plan remains `DRAFT`; this phase adds no treatment-plan export path. Clinician review is therefore mandatory before any later phase may approve or export it.

## Shared interface migration

**OLD**: `core.models.TreatmentPlan(items, transcript_segment_ids)`.

**NEW**: `models.treatment_plan.TreatmentPlan` with typed sections, medication records, version/status metadata, fact IDs, and per-field evidence.

**REASON**: unstructured strings cannot enforce medication completeness or field-level transcript provenance.

**MIGRATION**: `core.models` re-exports the new type. A deprecated `items` field and a computed `transcript_segment_ids` view preserve Phase 7 callers. Existing SQLite columns remain; schema v8 adds `structured_json`, `fact_ids_json`, and `status` and makes treatment rows append-only.

## Consequences

- Explicit imperatives such as “give paracetamol 1 gram three times a day” can become medication orders.
- A diagnosis alone can never produce treatment.
- Explicit statements that no medication will be started are recorded as pending decisions, while the pharmacological section remains `Not mentioned.`
- The local rule extractor is intentionally conservative. Unrecognised drug or management phrasing passes through without inventing a structured treatment and requires future clinician-reviewed vocabulary expansion.
